The Banner Capability Map

How to find what your institution already owns in Banner, and does not use, from your own database in an afternoon.

A method article. Everything here uses public Banner and Oracle data-dictionary objects that anyone can look up. No institution-specific data appears anywhere in it.

Every college running Banner pays Ellucian for a broad platform, and every one of them uses only part of it. The trouble is that nobody can easily say which part. So when a department asks to buy a new product, the honest answer is usually a shrug, and the easy answer is to buy it, sometimes for a capability Banner already ships and the college already owns.

This article shows how to replace the shrug with a measured answer, using nothing but read-only queries against your own Banner database. The idea is simple enough to hold in your head, and the evidence comes straight from Banner itself.

The idea in one picture: a capability is a room

Think of any Banner capability, Fixed Assets, Event Management, Workflow, as a room. Banner ships the doors: the screens (forms) you navigate to. Your security setup decides who holds a key: which users can reach those screens. And the data inside the room is whether anyone actually walks in and uses it.

Not installed
Banner offers it, but the room was never built here.

That is the whole mental model. The rest of this article is just how to ask Banner those three things precisely.

Three questions, three public tables

1. Do the screens exist?

Banner keeps a catalogue of every object, forms, jobs, menus, in GUBOBJS. Filtering it to forms whose names match a module's prefix tells you the capability is actually installed, not an orphan table. Fixed Assets forms start with FFA:

-- the screens Banner ships for Fixed Assets
SELECT gubobjs_name, gubobjs_desc
  FROM gubobjs
 WHERE gubobjs_objt_code = 'FORM'
   AND gubobjs_name LIKE 'FFA%'
 ORDER BY gubobjs_name;

You get the form codes (FFAMAST, FFADEPR, and so on) and their descriptions. If this returns rows, the capability is installed. If it returns nothing, the module was never delivered.

2. Can anyone reach them?

Banner resolves security access through the view GUVUACC. Counting the distinct users who can reach a module's objects tells you whether the door is even open. This is the same access data a good security review reads:

-- how many real users can reach the module's objects
SELECT COUNT(DISTINCT guvuacc_user)
  FROM guvuacc
 WHERE guvuacc_object LIKE 'FFA%'
   AND guvuacc_role NOT IN
       ('BAN_DEFAULT_NO_ACCESS', 'BAN_DEFAULT_CONNECT');

Two cautions. This is "can reach", not "uses": it is the size of the open door, not the traffic through it. And exclude the default no-access roles, or everyone looks like they have access to everything.

3. Is there data, and is it recent?

This is the judge. Every Banner capability has a canonical table that holds its real records. For Fixed Assets it is the asset master, FFBMAST. Count it, and read the newest activity date. Banner puts an _ACTIVITY_DATE column on almost every table:

-- the judge: how much is in the room, and how fresh
SELECT COUNT(*)                     AS records,
       MAX(ffbmast_activity_date)   AS last_activity
  FROM ffbmast;

Zero records means the capability is owned and not used, no matter how many screens ship or how many people hold keys. Records with a last activity years in the past means it was abandoned. Recent records means it is live.

The verdict

Put the three answers together and each capability lands in one bucket:

The canonical table is not there at allNot installed
It is empty, and Banner is meant to have itOwned, not used
It is empty, but a custom table quietly does the jobCustom-built
It is empty by design (housing at a college with no residence halls)Expected absent
It has data, but nothing recentAbandoned
It has recent activityIn use

Read the whole module, not one table

One empty table is a hint. A whole module of empty tables is a finding. Oracle's own statistics give you the size of every table for free, so you can census an entire module and say how little of it holds data. And DBA_TAB_COMMENTS gives you Banner's plain-English description of each table, so the reader sees what each one is:

-- census a whole module, with each table's description
SELECT t.table_name, t.num_rows, c.comments
  FROM dba_tables t
  LEFT JOIN dba_tab_comments c
         ON c.owner = t.owner AND c.table_name = t.table_name
 WHERE t.owner = 'FIMSMGR'
   AND t.table_name LIKE 'FF%'
 ORDER BY t.num_rows DESC NULLS LAST;

A line like "only N of M tables in this module hold any data" lands harder than a single empty count, and DBA_TAB_COMMENTS turns a wall of codes into readable evidence: FFBMAST becomes "Fixed Asset Master table".

Three ways to fool yourself

Empty is not the same as unlicensed. A capability nobody ever paid for would also be empty. This method measures use, not entitlement. Before telling a department "you already own this", confirm it is in your current Ellucian license. You are showing the door and the traffic; the contract is a separate question.
Do not judge by whether a report exists. It is tempting to ask "is there a report on this module?" But a capability can be used entirely inside Banner, through its own screens and native output, and never have a custom report built on it. A missing report proves nothing. Ask the data and the screens, never the report list.
Watch the neighbours and the validation tables. A module's canonical table can be empty while a sibling holds data for a related purpose (buildings defined for class scheduling even when event bookings are dead; certifications tracked even when the skills matrix is empty). Always name the one table the verdict rests on, and skip Banner's validation tables (a V in the third position of the name, like FFVACON) so their handful of seed codes do not read as real use.

The tool

All of this fits in one script. It reads a curated catalogue of capabilities, asks the three questions for each, censuses each module, pulls the table descriptions, and writes two things: a spreadsheet, and a self-contained interactive page where you click a capability and see its screens, its tables, and the numbers behind the verdict. It touches nothing but read-only queries, and it produces your map from your database. Nobody's numbers travel anywhere.

# one command, your own read-only Banner connection in a .env file
python bcm_report.py --out capability_map.xlsx --html capability_map.html

The output is a standing inventory. You do not run it in response to a purchase request; you keep it on the shelf, and when a department proposes buying a tool, you already have the row that says whether Banner does it, whether you own it, and whether anyone uses it.

This is a method, not a claim about any institution. Run it against your own Banner and the answers are entirely your own. Assembled from public Banner and Oracle data-dictionary knowledge that anyone can look up.
